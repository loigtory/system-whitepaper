# 采集策略重构 V1 执行看板（2026-06-09）

## 目标

让 `system-whitepaper` 在不接入 Browser Use、Stagehand、Crawlee 的前提下，先用本地 Playwright 和确定性策略提升页面取证质量。V1 的退出标准不是“能写稿”，而是 ADP 真实采集能产生可用于业务流程归纳的证据。

## 基线

- 设计文档：`docs/superpowers/specs/2026-06-06-evidence-capture-strategy-design.md`
- 实施计划：`docs/superpowers/plans/2026-06-06-evidence-capture-strategy-phase1.md`
- 当前问题基线：旧 ADP 归档中有菜单、页面和动作，但 `containers=0`、`observed flows=0`、`workflow steps=0`
- 关键约束：不新增云浏览器依赖；不让模型或 agent 读取 secrets；真实 ADP/SIT 采集需单独授权

## V1 退出门槛

- `npm run test:gate:auto -- --dry-run` 能根据变更文件选择 quick/core/full
- quick gate 通过
- ADP fresh reset 采集后满足：
  - `containers > 0` 或等价 page-internal surfaces > 0
  - `operation-spec` observed flows > 0
  - `workflow-spec` steps > 0
- 证据不足时，正式 narrative 节点必须被阻断或明确标记不可进入正式写稿

## 合并顺序

1. V1-E 先合并，降低后续任务的验证和交接成本。
2. V1-A 后合并或确认已合并，保证策略函数可测试。
3. V1-B 合并 collector 集成。
4. V1-C 合并 flow gate。
5. V1-D 最后执行真实 ADP 验证并写 checkpoint。

## Checkpoint 规则

每个任务包完成时，在 `docs/checkpoints/` 写一份短 checkpoint，文件名建议：

`YYYY-MM-DD-v1-<task-id>-checkpoint.md`

必须包含：

- 分支/提交
- 完成内容
- 验证命令和结果
- 剩余风险
- 是否需要真实 ADP/SIT 授权
- 下一步建议

当 chat 上下文过长、切换新 chat、真实采集中止或 ADP 指标未达标时，也必须写 checkpoint。

## 推荐验证命令

- 文档/计划变更：`npm run test:gate:auto -- --dry-run`
- helper / operation spec 变更：`npm run test:gate:auto`
- collector / auth / DB / readiness 变更：先跑 targeted tests，再由 `npm run test:gate:auto -- --dry-run` 确认是否需要 full gate
- 真实 ADP 采集：只在用户授权后运行 batch/pipeline reset 命令

## 明确不做

- 不接入 Browser Use、Stagehand、Crawlee
- 不推远程大版本
- 不让 agent 或模型直连数据库
- 不因为 quality-report 通过就忽略 Golden Eval 或流程证据为空的问题
