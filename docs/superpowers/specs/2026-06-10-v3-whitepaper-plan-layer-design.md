# V3 Whitepaper Plan Layer Design

## Context

V1 and V2 moved workflow evidence and business-process reasoning into deterministic artifacts. V3 addresses the next quality risk: the AI writing node can still organize prose directly from several compact artifacts. That makes it harder to prove that business purpose, workflow, and function summaries came from the approved evidence chain.

ADP remains only a pilot system. The plan layer must be generic enough for finance, HR, internal foundation, workflow, reporting, integration, and other internal systems. Domain wording may appear only when it is present in source evidence or an explicit upstream profile artifact has already produced it.

## Decision

Add `whitepaper-plan.json` as the deterministic writing contract between evidence/truth artifacts and AI narrative generation.

The AI Provider may write prose, but it must follow the plan:

- chapter mapping,
- required coverage items,
- allowed facts,
- boundary and pending items,
- forbidden items,
- writable claim coverage hints,
- business-process and workflow status boundaries.

The plan is generated by scripts from current artifacts. It is not generated by the AI model and it must not include raw `evidence.json`, screenshots, cookies, secrets, DB credentials, connection strings, private URLs, or customer samples.

## Goals

- Provide one compact, structured writing plan for Phase3B.
- Keep every required narrative item traceable to `verified-claims`, `business-process-model`, `workflow-spec`, `operation-spec`, or `evidence-summary`.
- Keep non-writable claims out of body assertions; they may only appear as pending/boundary items.
- Make stale, missing, forged, or uncovered plan items block formal readiness.
- Preserve observed/inferred/candidate/pending boundaries in the narrative prompt and gates.

## Non-Goals

- No Browser Use, Stagehand, Crawlee, or remote browser framework.
- No AI-generated truth model or AI-generated plan.
- No ADP golden facts in generation input.
- No hardcoded finance, HR, ADP, or internal-platform templates in the default builder.
- No weakening of V1/V2 workflow and business-process gates.

## Artifact Contract

`whitepaper-plan.json` version 1 contains:

- `artifactType: "whitepaper-plan"`.
- `version: 1`.
- `generatedAt`.
- `system`.
- `sourceArtifacts` with current fingerprints for available upstream artifacts.
- `derivation` with builder, algorithm version, source hash, and content hash.
- `chapters`: ordered chapter plans.
- `requiredItems`: flattened required body items that must be covered by the pending-review markdown.
- `allowedFacts`: facts permitted for body prose.
- `pendingItems`: facts or boundaries that must remain pending/unverified.
- `forbiddenItems`: explicit prohibitions for body prose.
- `metrics`.
- `rules`.

Required items must include stable `id`, `chapter`, `status`, `text`, `terms`, `source`, `evidence`, and optional `claimId`. Required body items may only reference writable verified claims or deterministic workflow/business-process facts.

Pending items may reference non-writable or weak claims, but their claim ids must not be exposed to the prompt as body citation markers.

## Data Flow

```text
verified-claims + business-process-model + workflow-spec + operation-spec + evidence-summary
  -> build-whitepaper-plan.js
  -> whitepaper-plan.json
  -> phase3b compact prompt input
  -> AI narrative fragments
  -> fact-check / narrative gate required-item coverage
  -> truth-readiness plan gate
```

## Readiness Gate

Truth readiness adds `gates.whitepaperPlan`.

Pass criteria:

- `whitepaper-plan.json` exists for formal review.
- Artifact contract is valid.
- Source fingerprints match current upstream artifacts.
- Deterministic recomputation from current inputs produces the same content hash.
- Required items exist when writable claims or business processes exist.
- Required item coverage in `fact-check-report.json` or `narrative-quality-report.json` meets the configured plan threshold.

Blocker ids:

- `whitepaper-plan.spec-missing`
- `whitepaper-plan.spec-invalid`
- `whitepaper-plan.lineage-stale`
- `whitepaper-plan.forged-plan`
- `whitepaper-plan.required-coverage`

Suggested rerun nodes:

```text
whitepaper-plan, narrative, fact-check, quality, truth-readiness
```

## Prompt Safety

Phase3B should inline the compact plan before fallback artifacts and instruct the AI:

- use `whitepaper-plan` as the primary writing contract;
- use other compact artifacts only to support the plan;
- do not read `evidence.json`, `whitepaper.draft.md`, screenshots, repo scripts, secrets, `.playwright-*`, or database files;
- do not promote inferred/candidate items to observed facts;
- do not cite non-writable claim ids in body sections.

## Testing Strategy

- Builder contract test for a generic finance fixture.
- Negative contract test rejecting secrets/URLs/connection-like strings.
- Prompt contract test showing Phase3B inlines compact `whitepaper-plan`.
- Fact-check or narrative test blocking missing required plan items.
- Readiness tests for missing/stale/forged/low-coverage plan artifacts.
- Pipeline node tests confirming `whitepaper-plan` runs after `business-process` and before `narrative`.

## Acceptance Criteria

- `whitepaper-plan.json` is deterministic and source-fingerprinted.
- Phase3B prompt uses the plan as the first writing contract.
- Missing required plan body items block formal review.
- Missing, stale, malformed, or forged plans block `truth-readiness`.
- Non-writable claims only appear as pending/boundary items.
- Generic non-ADP fixtures do not receive ADP-specific plan wording unless source evidence contains it.
